## 1. What can AgentTune (and AuditKIT) do for training and evaluation?

### Takeaway
AgentTune 1.1.3 is a real RL trainer, not only a rollout helper. One entry point, `create_agentic_trainer(algorithm=...)`, wraps TRL 1.7.1 for GRPO, RLOO, DPO, PPO and BCO. Its own multi-turn tool-calling rollout loop runs with transformers, vLLM or API engines. It masks tool-output tokens out of the loss (`env_mask`), accepts LoRA through `peft_config`, and has explicit, documented support for Tiny Aya's missing tool template through a fallback prompt that folds tool results into user turns. `create_distill_trainer` gives an AgentTune-native SFT path (LoRA + TRL SFTTrainer, completion-only loss) and accepts a custom `trainer_factory`. AuditKIT reads AgentTune's `trajectories.jsonl` directly. It provides deterministic tool-call metrics (validity, F1, trajectory match, redundant calls, loop detection) and verified outcome oracles. The main caveats: the evidence of real GPU runs is on SmolLM2-360M and Qwen2.5-3B, not Cohere, with no T4 or timing data. The Unsloth backend is described as unofficial.

### Cited Findings
**Algorithms and backends**
- AgentTune describes itself as "an RL trainer built on TRL that runs GRPO, PPO, DPO, RLOO, and BCO through one entry point and trains LLM agents to call tools during rollouts". "All five use agentic tool-calling rollouts rather than plain-text generation." — [AgentTune README (installed METADATA)](https://github.com/Lexsi-Labs/AgentTune)
- Factory signature: `create_agentic_trainer(algorithm: str, backend: str = "auto", **kwargs)`. `"auto"` uses Unsloth if it can be imported and otherwise TRL; `"trl"` and `"unsloth"` pin a backend. — [agenttune/core/backend_factory.py](file:///C:/Users/HP/Projects/aya-db-agent/.venv/Lib/site-packages/agenttune/core/backend_factory.py)
- Both `backends/trl/agentic/{grpo,rloo,dpo,ppo,bco}` and `backends/unsloth/agentic/{grpo,rloo,dpo,ppo,bco}` exist, plus `backends/unsloth/sft/sft.py` (an `UnslothSFTTrainer`). The Unsloth GRPO backend loads through `FastLanguageModel.from_pretrained` with `load_in_4bit` defaulting to True. — [agenttune/backends/unsloth/agentic/grpo/agentic_grpo.py](file:///C:/Users/HP/Projects/aya-db-agent/.venv/Lib/site-packages/agenttune/backends/unsloth/agentic/grpo/agentic_grpo.py)
- TRL is "the supported, tested (real GPU test coverage), documented path". Unsloth is "optional, unofficial", described as self-service and not benchmarked, and installed with `pip install unsloth==2026.8.19 --no-deps`. Once imported, Unsloth patches transformers model classes process-wide, so later plain loads can fail (e.g. `'Qwen2Attention' object has no attribute 'apply_qkv'`). The page says to keep Unsloth and TRL work in separate processes or set `PURE_TRL_MODE=1`. — [AgentTune docs: Backend Selection](https://github.com/Lexsi-Labs/AgentTune/blob/main/docs/getting-started/backend-selection.md)
- Dependency pins: `torch==2.11.0`, `trl==1.7.1`, `transformers<6,>=5.15`, Python >= 3.12. The `[vllm]` extra resolves to vllm 0.22.1 ("Linux + CUDA only"). `flash-attn` is an optional extra. — [AgentTune README / METADATA](https://github.com/Lexsi-Labs/AgentTune)

**Multi-turn rollouts, environment feedback, masking, vLLM**
- The TRL GRPO wrapper supports "Agentic GRPO (completions as lists of message dicts with tool calls/results)", "Custom rollout_func / environment_factory" and "vLLM-accelerated generation". If `tools` are passed without a `rollout_func`, it builds one from AgentTune's own rollout engine. The source comment says this is because "the installed TRL only executes `tools=` natively on transformers>=5 (and can't schema a BaseTool object)". It also patches `GRPOTrainer._generate_single_turn` so the rollout_func drives generation under both transformers and vLLM. The cap on tool turns per episode is `max_steps_per_turn` (default 20). — [agenttune/backends/trl/agentic/grpo/agentic_grpo.py](file:///C:/Users/HP/Projects/aya-db-agent/.venv/Lib/site-packages/agenttune/backends/trl/agentic/grpo/agentic_grpo.py)
- Loss masking: the rollout records a per-token `tool_mask`. Model-generated tokens get 1 and tool-result tokens get 0 (`all_tool_mask.extend([0] * len(tool_ids))`). It is returned to TRL as `env_mask`, with a code comment saying 'The key MUST be "env_mask"'. — [agenttune/agentic/rollout_engines/rollout_factory.py (lines ~1303, 1439–1445, 2079, 2365)](file:///C:/Users/HP/Projects/aya-db-agent/.venv/Lib/site-packages/agenttune/agentic/rollout_engines/rollout_factory.py)
- Rollout engines: `transformers` (local), `vllm` (fast batched) and `api` (any LiteLLM provider), each usable on its own. The vLLM engine takes `dtype` and `gpu_memory_utilization`, and passes through `quantization_config` (e.g. bnb 4-bit) for the transformers engine. — [AgentTune README](https://github.com/Lexsi-Labs/AgentTune); [rollout_factory.py create_rollout_engine](file:///C:/Users/HP/Projects/aya-db-agent/.venv/Lib/site-packages/agenttune/agentic/rollout_engines/rollout_factory.py)
- Rewards: 26 named reward functions in `REWARD_REGISTRY`, including SQL ones (`correctness_reward`, `structure_reward`, `query_reward`, `sql_format_reward`), `tool_chain_reward` and `exploration_reward`, plus `combine_rewards(...)`. Any Python callable `(prompts, completions, **kwargs) -> list[float]` also works, and rollout `trajectories` are forwarded to reward functions as extra fields. — [AgentTune README](https://github.com/Lexsi-Labs/AgentTune); [agenttune/agentic/rewards/builtin_rewards/sql.py](file:///C:/Users/HP/Projects/aya-db-agent/.venv/Lib/site-packages/agenttune/agentic/rewards/builtin_rewards/sql.py)
- DPO has three modes: (1) offline chosen/rejected, (2) "reward-ranked rollouts" where completions are generated each step and `reward_funcs` picks chosen and rejected, and (3) "agentic tool-calling rollouts", which is mode 2 with multi-turn tool calls. It uses the standard `DPOTrainer`, not the experimental OnlineDPO. — [agenttune/backends/trl/agentic/dpo/agentic_dpo.py](file:///C:/Users/HP/Projects/aya-db-agent/.venv/Lib/site-packages/agenttune/backends/trl/agentic/dpo/agentic_dpo.py)
- SFT / distillation: `create_distill_trainer` collects teacher trajectories (hand-authored, pre-built, or live `teacher_engine` plus `tasks`). It trains a student with "a built-in LoRA+TRL SFTTrainer", and `trainer_factory=` overrides the built-in TRL/LoRA factory entirely. — [AgentTune README](https://github.com/Lexsi-Labs/AgentTune). The verified distillation run used "TRL SFTTrainer, LoRA, completion-only loss". — [AgentTune REAL_EXAMPLES](https://github.com/Lexsi-Labs/AgentTune/blob/main/examples/REAL_EXAMPLES.md)

**Cohere specifics**
- "None of the Cohere hackathon models (Tiny Aya, Aya Expanse, Aya Vision, North) ships a chat template that renders `tools`: Tiny Aya has only a `default` template, and it renders a `tool` turn as an empty turn." AgentTune falls back by putting tool schemas in the system prompt (`tools_fallback_prompt`) and passing tool results back as user turns (`tool_result_format`). It still parses Cohere's native `<|START_ACTION|>…<|END_ACTION|>` format. The README includes a Tiny Aya GRPO example with `use_vllm=False` and a LoRA `peft_config`, which "runs on CPU or a Mac without vLLM". — [AgentTune README](https://github.com/Lexsi-Labs/AgentTune)
- Code comments say that `ensure_lora_targets` exists because PEFT would otherwise raise "Please specify target_modules" for Cohere / Cohere2. They also note that Tiny Aya Fire's template rejects non-alternating user/assistant sequences. — [rollout_factory.py](file:///C:/Users/HP/Projects/aya-db-agent/.venv/Lib/site-packages/agenttune/agentic/rollout_engines/rollout_factory.py); [agentic/distill_trainer.py](file:///C:/Users/HP/Projects/aya-db-agent/.venv/Lib/site-packages/agenttune/agentic/distill_trainer.py)

### Inferences
- For the "must use AgentTune" requirement, AgentTune can own every training stage. SFT can go through `create_distill_trainer`, which can even wrap the project's own tested QLoRA trainer through `trainer_factory=`. RL can go through `create_agentic_trainer(algorithm="grpo"|"rloo"|"dpo", backend="trl")`, and evaluation through AuditKIT's `episodes_from_agenttune`. The project already depends on AgentTune's `_render_chat_template` and rollout loop, so the GRPO path reuses the exact prompt format the SFT data is built in.
- Pass `backend="trl"` explicitly. The default `"auto"` silently switches to Unsloth if it is installed, and Unsloth patches classes process-wide.
- AgentTune's documented Unsloth pin (`unsloth==2026.8.19`) predates the Unsloth fixes for tiny-aya tokenization (merged 2026-09-27) and for Cohere logit scale in the fused CE loss (merged 2026-09-18; see section 2). The pinned Unsloth path is therefore a correctness risk for Tiny Aya.
- RLOO and GRPO both showed reward climbing in AgentTune's verified runs, while PPO did not. Agentic RAG GRPO showed zero within-group variance. For a weak base model (Tiny Aya untuned scored ~0–3% success on the project dev split), the same failure mode is likely: all-zero groups give no gradient. So GRPO should start from the SFT checkpoint and use partial-credit rewards, not run on the base model.
- Tiny Aya has no tool template, so tool results are folded into user turns. In a TRL SFTTrainer run with completion-only or assistant-only loss, check that the folded tool-result user turns are actually masked. The project's own `src/ayadb/sft.py` collator may already do this. The GRPO path masks them through `env_mask`.

### Gaps
- No public evidence of an AgentTune run on a Cohere model on GPU, on a T4, or with timing and VRAM numbers. REAL_EXAMPLES has none, and the known-issues page says nothing about Cohere, fp16 or vLLM.
- Did not verify whether `create_distill_trainer`'s built-in factory masks folded tool-result user turns in multi-turn conversations, or only the final completion.
- Did not test whether AgentTune's GRPO + `use_vllm=True` works with LoRA on vLLM 0.22.1 on a T4.

## 2. Does Unsloth support Tiny Aya / Aya Expanse (Cohere / Cohere2) for QLoRA SFT and GRPO on a T4?

### Takeaway
Probably yes, with caveats. Unsloth supports T4 (CUDA capability 7.0+). Its 2026 commit history shows Cohere and Cohere2 model loops being actively maintained, including tiny-aya-specific fixes. Several of those fixes only landed in Sept–Oct 2026, though, and they were silent-correctness bugs (wrong token IDs, logit scale dropped in the loss), so only a very recent Unsloth release is safe. No Tiny Aya notebook or official GRPO memory table was found. The best available GRPO number is about 13 GB for an 8B Llama in the free-Colab T4 notebook (early 2025).

### Cited Findings
- Minimum CUDA capability is 7.0 ("V100, T4, Titan V, RTX 20 & 50, A100, H100, L40 etc"). Minimum fine-tuning VRAM: 3B needs 3.5 GB with QLoRA 4-bit or 8 GB with LoRA 16-bit; 8B needs 6 GB with QLoRA or 22 GB with LoRA. — [Unsloth requirements](https://unsloth.ai/docs/get-started/fine-tuning-for-beginners/unsloth-requirements)
- GRPO memory (Feb 2025, free-Colab notebooks): Llama 8B ~13 GB, Phi-4 14B ~15 GB, Qwen 3B ~7 GB. Unsloth claims GRPO uses "80% less VRAM than Hugging Face + FA2", and the Qwen2.5-1.5B R1-Zero reproduction needs 7 GB. — [Reddit r/MachineLearning thread (Unsloth author replying)](https://reddit.birdcat.cafe/r/MachineLearning/comments/1ik3nkr/p_grpo_fits_in_8gb_vram_deepseek_r1s_zeros_recipe); [Unsloth R1 reasoning blog](https://unsloth.ai/blog/r1-reasoning)
- Tiny Aya fix: "Rebuild CohereTokenizer from tokenizer.json when transformers v5 changes its ids". It fixes tiny-aya on transformers 5.x, where a hard-coded pre-tokenizer changed token IDs. Merged 2026-09-27. — [unslothai/unsloth PR #12130](https://github.com/unslothai/unsloth/pull/12130)
- "Apply logit scale on the fused cross entropy path": the fused loss dropped Cohere's and Granite's logit scale, so training diverged from the reference. Merged 2026-09-18. — [unslothai/unsloth PR #11277](https://github.com/unslothai/unsloth/pull/11277)
- "Fix returned logit scaling and softcapping when labels are provided": Cohere logits came back "16x off". Closed 2026-10-08. — [unslothai/unsloth PR #13069](https://github.com/unslothai/unsloth/pull/13069)
- A decode crash past the RoPE cache was fixed for Gemma2, Cohere, Granite and FalconH1 (2026-10-19). — [unslothai/unsloth PR #14199](https://github.com/unslothai/unsloth/pull/14199)
- An open PR (2026-11-03) adds CUDA-graph decoding for every FastModel model "including Cohere 2", reporting 3–7x per-token speedups on T4. — [unslothai/unsloth PR #16587](https://github.com/unslothai/unsloth/pull/16587)
- A 2x T4 batched-generation crash fix (2026-09-29) left the "Cohere and Granite loops… unchanged". — [unslothai/unsloth PR #12290](https://github.com/unslothai/unsloth/pull/12290). A separate fix covers GRPO generation on a non-default GPU (cuda:0/cuda:1 mismatch). — [unslothai/unsloth PR #15677](https://github.com/unslothai/unsloth/pull/15677)
- Older Aya report: saving a 4-bit aya-expanse-8b with `merged_4bit_forced` raised `AttributeError` (2025). — [unslothai/unsloth issue #2488](https://github.com/unslothai/unsloth/issues/2488)
- No Tiny Aya-specific Unsloth notebook was found, and a search of `hf://models/unsloth` for "tiny-aya" returned no pre-quantized Unsloth uploads. — [Hugging Face Hub search via MCP, unsloth namespace]; [web search result summary](https://unsloth-readme.static.hf.space/README.md)
- AgentTune's own Unsloth integration pins `unsloth==2026.8.19 --no-deps` and `unsloth_zoo>=2026.8.13`. — [AgentTune README](https://github.com/Lexsi-Labs/AgentTune)

### Inferences
- If Unsloth is used, use a release from after 2026-10-19, not AgentTune's 2026.8.19 pin, and validate it on a held-out sample: loss parity against plain TRL/PEFT for a few steps, and tokenization round-trip. The Cohere bugs above were silent: training ran but diverged.
- QLoRA SFT of Tiny Aya (3.35B) and Aya Expanse 8B fits a 16 GB T4 by Unsloth's own minimums. GRPO on 8B (~13 GB for Llama-8B in the 2025 notebook) would be very tight with ~2–4k-token multi-turn contexts. Cohere's ~256k vocabulary inflates logits memory (background knowledge: Aya Expanse vocab 256,000; verify Tiny Aya's in config.json). GRPO on a T4 is realistic only for Tiny Aya.
- Unsloth's main benefit for this project is memory and speed (fused CE, which avoids materialising full fp32 logits over the big vocabulary). The cost is extra integration risk on a 10-day timeline. The plain TRL/PEFT path the project already runs on Kaggle is the lower-risk default.

### Gaps
- No measured Unsloth GRPO VRAM or throughput for Cohere2 / Tiny Aya on T4. The 2025 figures are for Llama/Qwen/Phi.
- Could not confirm which Unsloth release (version string) first contains PRs #11277, #12130 and #14199.
- Could not read Tiny Aya's `config.json` directly because the repo is gated for the connected HF account. Architecture details come from mirrors (section 3).

## 3. TRL GRPOTrainer multi-turn / tool support, and vLLM for Tiny Aya on T4

### Takeaway
TRL (docs at v1.17.1; the project pins 1.7.1 through AgentTune) supports multi-turn tool GRPO three ways: `tools=`, `environment_factory=` and a custom `rollout_func`. The native `tools=` and environment paths need a prefix-preserving, tool-aware chat template and list supported families that exclude Cohere. Tiny Aya therefore has to go through a custom rollout_func, which is exactly what AgentTune provides. vLLM supports `Cohere2ForCausalLM` (Tiny Aya's architecture) with LoRA and nominally supports T4 (compute capability 7.5, fp16 only). Community reports show Turing-specific kernel and V1-engine breakages, so vLLM on a T4 is a gamble. On L4/A10G/L40S (Ampere/Ada, bf16) it is the standard path.

### Cited Findings
- "The GRPO tool call loop requires the chat template to be *prefix-preserving*… For known model families (e.g. Qwen3, DeepSeek-V3), TRL automatically swaps in a patched training template." The supported agent-training models listed are Gemma4, GLM-4-MoE, GPT-OSS, Llama 3.1/3.2, Qwen2.5/3/3-VL/3.5/3.6 and others, and "Compatibility with all LLMs is not guaranteed". `max_tool_calling_iterations` caps tool turns. — [TRL GRPO Trainer docs](https://huggingface.co/docs/trl/grpo_trainer)
- `environment_factory` "requires `transformers>=5.2.0`", creates one environment instance per rollout, exposes public methods as tools, and supports `reset` and `get_reward`. It is "experimental". — [TRL GRPO Trainer docs](https://huggingface.co/docs/trl/grpo_trainer); [TRL OpenEnv docs](https://huggingface.co/docs/trl/openenv#how-environmentfactory-works)
- `rollout_func: Callable[[list[str], GRPOTrainer], dict]` must return `prompt_ids`, `completion_ids` and `logprobs`; "Any other fields are forwarded to the reward functions". It is also experimental. — [TRL GRPO Trainer docs](https://huggingface.co/docs/trl/grpo_trainer)
- vLLM modes: in colocate (the default), vLLM shares GPU memory with training, and `vllm_gpu_memory_utilization` defaults to 0.3 with `vllm_enable_sleep_mode` suggested for OOM. Server mode runs vLLM "in a separate process (and using separate GPUs)", started with `vllm serve … --weight-transfer-config '{"backend": "nccl"}'`. QLoRA is done with `quantization_config` plus `peft_config`. — [TRL GRPO Trainer docs](https://huggingface.co/docs/trl/grpo_trainer)
- An OpenEnv multi-turn (Wordle) GRPO tutorial uses `use_vllm=True, vllm_mode="colocate", vllm_gpu_memory_utilization=0.15, vllm_max_model_length=3072`. — [OpenEnv Wordle GRPO tutorial](https://huggingface.co/docs/openenv/tutorials/wordle-grpo#set-grpo-config)
- Tiny Aya architecture (from public mirrors of the gated configs): `Cohere2ForCausalLM` / `cohere2`, 36 layers, 16 attention heads, 4 KV heads, sliding window 4096 with pattern 4 (3 sliding layers to 1 full), RoPE theta 50,000. — [1-800-LLMs/tiny-aya-global config.json mirror](https://huggingface.co/1-800-LLMs/tiny-aya-global/blob/main/config.json). Vultr describes Tiny Aya Global as 3.35B with ~8K usable context and lists vLLM and SGLang deployment. — [Vultr model page](https://docs.vultr.com/models/cohere-tiny-aya/tiny-aya-global)
- vLLM's supported-models table lists `CohereForCausalLM, Cohere2ForCausalLM` (Command-R, Command-A; e.g. `c4ai-command-r7b-12-2024`) with LoRA ✅ and PP ✅. — [vLLM supported models](https://docs.vllm.ai/en/latest/models/supported_models.html)
- vLLM GPU requirement: "compute capability 7.5 or higher (e.g., T4, RTX20xx, A100, L4, H100, B200, etc.)", Linux only, prebuilt with CUDA 12.9. — [vLLM GPU installation](https://docs.vllm.ai/en/latest/getting_started/installation/gpu.html)
- Community reports on Turing: you must force `--dtype float16` ("bfloat16 is only supported on GPUs with compute capability at least 8.0"). The V1 engine fell back to FlexAttention and crashed at init on Turing in v0.11.0 (fix vllm#24022 pending at the time). A Triton attention kernel needing more shared memory than Turing has broke Gemma 4 (head_dim 512) as recently as v0.30.0rc1. — [Apertus Turing discussion](https://hug-proxy.pages.dev/swiss-ai/Apertus-8B-Instruct-2509/discussions/21); [vLLM forum: Turing shared-memory error](https://discuss.vllm.ai/t/title-outofresources-shared-memory-98304-65536-on-turing-sm75-global-attention-layers-with-head-dim-512/2990)
- AgentTune's own patch makes rollout_func work under TRL's vLLM path ("keeps the masking-aware tool-calling loop intact under vLLM"). — [agentic_grpo.py](file:///C:/Users/HP/Projects/aya-db-agent/.venv/Lib/site-packages/agenttune/backends/trl/agentic/grpo/agentic_grpo.py)

### Inferences
- For Tiny Aya, do not use TRL's native `tools=` or `environment_factory`, because the template is neither tool-aware nor in the supported list. Use AgentTune's rollout_func (auto-built from `tools=`), which already handles Tiny Aya's fallback format and `env_mask`.
- Tiny Aya's head_dim is 2048/16 = 128 if hidden size is 2048. That is unverified, but if true it avoids the head_dim-512 Turing failure seen with Gemma 4. Even so, vLLM 0.22.1 on a T4 with fp16 and sliding-window layers is untested here: budget half a day to try it, and keep `use_vllm=False` (transformers generation) as the fallback.
- On Kaggle 2x T4, TRL server mode fits the hardware shape: vLLM on GPU 1 and the trainer on GPU 0 over NCCL. If vLLM works on T4 at all, this is the fastest free configuration. Colocate mode on one T4 with a 3.35B model leaves little memory once a 0.3 utilization is reserved.
- fp16-only T4 training of a model released in bf16 risks overflow. The project's `sft.py` already carries an "fp16 overflow guard". RL with importance ratios is more sensitive than SFT, which is another reason to run the RL stage on L4/A10G/L40S in bf16.

### Gaps
- No direct confirmation that vLLM 0.22.x runs `Cohere2ForCausalLM` on sm_75 in fp16, or that LoRA hot-swap works on T4 in current vLLM. The only T4 LoRA failure report is from vLLM 0.4.x, 2024. — [AIcrowd forum](https://discourse.aicrowd.com/t/issues-using-llm-and-lora-adapter-on-nvidia-t4/10480)
- Did not confirm which TRL version first shipped `environment_factory`, `rollout_func` and `tools` in GRPO. AgentTune's comments imply the pinned 1.7.1 does not call `rollout_func` natively, hence its patch.
- Did not check whether TRL computes completion logprobs in chunks, which matters for logits memory with a ~256k vocabulary on 16 GB.

## 4. Other agentic RL frameworks (verl / verl-agent, SkyRL, OpenPipe ART, rLLM, Prime-RL)

### Takeaway
None is a sensible adoption for a solo 10-day T4/$25 project. verl and SkyRL target multi-GPU Ampere/Hopper clusters (examples use 4x 48 GB or H100/H200), and nothing found confirms T4 support. ART is the lightest (pip install, GRPO multi-step agents, Unsloth + vLLM, RULER auto-rewards) but does not mention Cohere and would duplicate AgentTune, which the track requires anyway. No sources were found for rLLM or Prime-RL hardware minimums.

### Cited Findings
- verl's agentic RL uses a server-based async rollout for multi-turn tool calls, and its example scripts default to SGLang (vLLM selectable). — [verl docs: Agentic RL Training](https://verl.readthedocs.io/en/latest/start/agentic_rl.html)
- verl's hardware table lists GRPO-LoRA on a single H100 for Qwen2.5-0.5B/1.5B/3B/7B, with the 7B at a much smaller max batch, and 4x H100 for Qwen2.5-32B. — [verl docs: Hardware Resource Needed for RL](https://verl.readthedocs.io/en/latest/perf/device_tuning.html)
- SkyRL "scales from a single GPU to multi-node clusters via Ray + SkyPilot", but its GSM8K template requests 4x 48 GB GPUs. — [SkyPilot SkyRL example](https://docs.skypilot.co/en/latest/examples/training/skyrl.html). A single-GPU SkyRL GRPO run used 1x H200 on Qwen2.5-1.5B (not multi-turn). — [YottaLabs guide](https://docs.yottalabs.ai/tutorials/training-and-fine-tuning/grpo-on-gsm8k-with-virtual-machine). SkyRL-Agent-14B reportedly took 20 hours on 8x H200. — [SourcePulse SkyRL summary](https://www.sourcepulse.org/projects/2410687)
- ART: "open-source RL framework that improves agent reliability by allowing LLMs to learn from experience". It trains multi-step agents with GRPO, serves the latest LoRA in vLLM, and offers RULER automatic rewards and a serverless W&B backend. It "should work with most vLLM/HuggingFace-transformers compatible causal language models, or at least the ones supported by Unsloth", "Gemma 3 does not appear to be supported", and Cohere is not mentioned. — [OpenPipe ART README](https://github.com/OpenPipe/ART)

### Inferences
- verl, SkyRL and Prime-RL depend on vLLM/SGLang and FSDP on bf16-capable GPUs. On T4 they inherit every vLLM Turing risk plus Ray/FSDP setup, which would plausibly cost several of the 10 days.
- ART on a rented L4/A10G is the only plausible alternative if AgentTune's GRPO path fails. But it builds on Unsloth, so the Cohere2 caveats in section 2 apply, and it would not count as "using AgentTune".

### Gaps
- No sources found on rLLM or Prime-RL minimum hardware or T4 compatibility. No verl / verl-agent statement on Turing or fp16.

## 6. Realistic throughput: SFT on 250–2,000 multi-turn episodes, and RL rollouts per hour

### Takeaway
One measured data point exists, from the project's own run: Tiny Aya Global Q8 GGUF under Ollama on the laptop RTX 5050 completed 160 multi-turn SQL episodes (mean 4.1 turns, 3.5 tool calls) in 850 s, about 5.3 s per episode or about 680 episodes/h sequentially. Everything else below is a first-principles estimate. QLoRA SFT on 2,000 × 2k-token episodes (≈4M tokens) should take roughly 1.5–3 h per epoch on one T4 for Tiny Aya, and about 2.5x that for Aya Expanse 8B. An L4 or A10G should be roughly 2–3x faster. A GRPO step of 32 eight-turn episodes plausibly takes ~8–12 min on a T4 with transformers generation and ~2–4 min on an L4 with vLLM. That means ~60–80 steps per 12-h Kaggle session, or ~100 steps for ≈$3–5 on an HF L4.

### Cited Findings
- Measured local rollout: run `20261104-010953-E-close-T08-k4` had model `hf.co/CohereLabs/tiny-aya-global-GGUF:Q8_0` (Ollama), n=160 (40 tasks × 4 repeats), temperature 0.8, `num_predict` 512, `num_ctx` 8192, `max_steps` 8, `wall_s` 850.1, `mean_turns` 4.07, `mean_tool_calls` 3.54, and `success_rate` 0.025. — [runs/20261104-010953-E-close-T08-k4/summary.json](file:///C:/Users/HP/Projects/aya-db-agent/runs/20261104-010953-E-close-T08-k4/summary.json); [config.json](file:///C:/Users/HP/Projects/aya-db-agent/runs/20261104-010953-E-close-T08-k4/config.json)
- Unsloth reports ~300 tokens/s inference on a 16 GB T4 (context unspecified). — [Unsloth R1 reasoning blog](https://unsloth.ai/blog/r1-reasoning)
- An open Unsloth PR reports 3–7x per-token decode speedups on T4 with CUDA graphs, including Cohere 2. — [unslothai/unsloth PR #16587](https://github.com/unslothai/unsloth/pull/16587)
- TRL's Jobs guide: a 3-epoch SFT of a 0.5B model on Capybara takes "a few hours on a10g-small". — [TRL: Training with Jobs](https://huggingface.co/docs/trl/jobs_training)

### Inferences
These are back-of-envelope estimates. Validate with a 20-step timing run before committing quota.
- **SFT token volume:** 250 episodes × ~2k tokens ≈ 0.5M tokens per epoch, and 2,000 episodes ≈ 4M tokens per epoch.
- **SFT compute:** LoRA with gradient checkpointing costs about 6 × N FLOPs per token (forward, recompute, backward through activations). For N = 3.35B that is ≈2×10¹⁶ FLOPs per 1M tokens. Assume a T4 sustains ~10–15 TFLOPS effective in fp16 QLoRA (spec peak ≈65 TFLOPS fp16 tensor, from background knowledge; dequantization and the 256k-vocab LM head cost extra). That gives **≈25–35 min per 1M tokens**: ~15 min/epoch for 250 episodes and ~1.5–3 h/epoch for 2,000 episodes on one T4. Aya Expanse 8B is ~2.4x more compute (~4–7 h/epoch at 2,000 episodes), which is feasible within one 12-h Kaggle session only for 1–2 epochs. DDP over Kaggle's 2x T4 roughly halves wall time. The project's `sft.py` currently pins `device_map={"":0}` (one GPU).
- **SFT on HF:** L4 (bf16, ~121 TFLOPS fp16/bf16 dense spec, background knowledge) or A10G should be ~2–3x a T4 in practice. A 2,000-episode Tiny Aya epoch then takes roughly 40–70 min, about $0.55–0.95 on L4. SFT is cheap; RL is where the budget goes.
- **Rollouts with transformers `generate` on a T4, fp16, batch 1:** decode is bandwidth-bound (~6.7 GB of weights against ~320 GB/s gives a ≤~45 tok/s ceiling, realistically ~20–30). An 8-turn episode with ~100–150 generated tokens per turn (~1–1.2k tokens) plus re-prefill takes ~40–70 s, so **~50–90 episodes/h per T4**. Batching 8–16 concurrent episodes might raise that to ~300–600/h if the AgentTune transformers engine batches across trajectories, which was not verified.
- **Rollouts with vLLM on L4/A10G:** continuous batching of a 3B model should give ~1–3k tok/s aggregate, so **~2,000–5,000 eight-turn episodes/h**. The laptop's Ollama measurement (~680/h sequential at ~4 turns) sits in between and costs nothing.
- **GRPO step estimate** (8 prompts × 4 generations = 32 episodes, ~2–4k tokens each): the training pass covers ~100k tokens with a reference forward (LoRA adapter disabled) at ~1.5x the SFT cost per token, roughly 2–5 min on a T4 and ~1–2 min on an L4. Total ≈ **8–12 min/step on T4 without vLLM** (≈60–80 steps per 12-h Kaggle session) and **≈2–4 min/step on L4 with vLLM** (100 steps ≈ 3.5–7 h ≈ $3–6).
- **Rejection sampling:** k=8 samples on 300 training tasks is 2,400 episodes, about 3.5 h on the laptop via Ollama (free, measured rate), ~1 h on an HF L4 with vLLM (≈$1), or ~4–8 h on a Kaggle T4 with batched transformers generation.

### Gaps
- No measured Tiny Aya training throughput (tokens/s) on T4, L4 or A10G anywhere, including the project (no `train_runtime` logs found in `experiments/` or `remote/`).
- Did not verify whether AgentTune's transformers rollout engine batches generation across trajectories, which drives the T4 rollout estimate by ~5–10x.
- Memory for GRPO with ~256k-vocab logits at 4k context on 16 GB is unmeasured. It could force shorter contexts or `max_completion_length` caps on T4.

## 7. Recommended stack and 10-day compute budget (SFT + one RL or rejection-sampling round)

### Takeaway
Route everything through AgentTune on its supported TRL backend: `create_distill_trainer`, or the existing QLoRA trainer plugged into it, for SFT, and `create_agentic_trainer(..., backend="trl")` for RL, with AuditKIT for evaluation. Do SFT on Kaggle T4 (free). Make the guaranteed RL step a rejection-sampling fine-tuning (RFT) round: sample on the free laptop GPU or Kaggle, filter with verified SQL execution, then re-SFT. If time allows, run one short AgentTune GRPO or RLOO run from the SFT checkpoint on an HF Jobs L4 (bf16, vLLM). Use Tiny Aya (3.35B) for RL. Use Aya Expanse 8B at most as an SFT-only comparison. Expected paid spend is about $10–15 of the $20–30 HF credits, leaving the rest as reserve.

### Cited Findings
- AgentTune entry points: `create_agentic_trainer(algorithm="grpo"|"rloo"|"dpo"|…)`, `create_distill_trainer(..., trainer_factory=...)`, and the Tiny Aya fallback prompt with a GRPO example using `use_vllm=False` and LoRA. — [AgentTune README](https://github.com/Lexsi-Labs/AgentTune)
- Pin `backend="trl"`, the tested path. Unsloth is unofficial and patches classes globally. — [AgentTune Backend Selection](https://github.com/Lexsi-Labs/AgentTune/blob/main/docs/getting-started/backend-selection.md)
- AgentTune GRPO/RLOO lifted rewards in its verified runs. PPO "did not reliably climb", and agentic-RAG GRPO had zero reward variance. — [AgentTune REAL_EXAMPLES](https://github.com/Lexsi-Labs/AgentTune/blob/main/examples/REAL_EXAMPLES.md)
- HF Jobs prices: L4 $0.80/h, A10G-small $1.00/h, L40S $1.80/h, A100 $2.50/h, billed per minute. — [HF Jobs pricing](https://huggingface.co/docs/hub/jobs-pricing)
- Modal Starter: $30/month free. — [Modal pricing](https://modal.com/pricing)
- AuditKIT reads AgentTune `trajectories.jsonl` with `episodes_from_agenttune`. Its tool metrics are ToolCallValidity, ToolCallF1, TrajectoryMatch, RedundantToolCalls and AgentLoopDetection, with verified outcome oracles. — [AgentTune README](https://github.com/Lexsi-Labs/AgentTune); [auditkit/metrics/agent.py](file:///C:/Users/HP/Projects/aya-db-agent/.venv/Lib/site-packages/auditkit/metrics/agent.py)

### Inferences
**Recommended stack**
1. **SFT (days 1–4):** run on Kaggle 2x T4 in fp16 QLoRA (r=16–32, all-linear; let AgentTune's `ensure_lora_targets` handle Cohere target modules). Wrap it as AgentTune `create_distill_trainer(trainer_factory=<project QLoRA trainer>)`, or use its built-in LoRA+TRL SFT after checking the tool-turn masking. Train on oracle/teacher trajectories rendered with AgentTune's `_render_chat_template` and Tiny Aya fallback format, exactly as at inference. Optionally use both T4s, through DDP or two hyperparameter configs in parallel.
2. **RL round A, guaranteed (days 4–6): rejection-sampling fine-tuning.** Sample k=4–8 episodes per training task from the SFT model at T≈0.8. Use the laptop RTX 5050 via Ollama (free, ~680 episodes/h measured for the base model) after a GGUF conversion of the merged adapter, or use AgentTune's rollout engine on Kaggle. Keep only episodes whose final answer passes execution-match. Optionally prefer the shortest successful episode per task, which rewards efficiency and fewer redundant calls. Then re-SFT on SFT data plus accepted samples. This is robust, needs no RL infrastructure, and directly targets success rate and efficiency. An AgentTune-native variant is DPO mode 3 (agentic tool-calling, reward-ranked rollouts): successful episodes are chosen, failed ones rejected.
3. **RL round B, optional (days 6–8): short GRPO or RLOO through AgentTune** from the RFT checkpoint on an HF Jobs L4 (bf16; `use_vllm=True, vllm_mode="colocate", vllm_gpu_memory_utilization≈0.3–0.4`). If vLLM fails on Cohere2, use `use_vllm=False` on an L40S. Suggested settings: LoRA, `num_generations=4–8`, `max_steps_per_turn=8`, `max_steps≈60–120`, lr ~1e-6–5e-6, and a composite reward of execution-match correctness (most weight) + valid-call format + a small per-call penalty / loop penalty. The SFT/RFT start is what makes groups non-degenerate. Push checkpoints to the Hub (`--hub_strategy checkpoint`) and set `--timeout`. If HF vLLM works quickly, a fallback is the same run on Kaggle (T4, `use_vllm=False`, ~60–80 steps per 12-h session).
4. **Eval (continuous, days 2–10):** AuditKIT `episodes_from_agenttune` on dev and test splits. Report verified success (AnswerAssertion / CustomPredicate SQL-result oracle), ToolCallValidity, RedundantToolCalls, AgentLoopDetection and mean turns/tokens. Run with Ollama locally where possible to save GPU quota.

**Compute budget (10 days)**

| Stage | Where | Est. GPU time | Est. cost |
|---|---|---|---|
| SFT sweeps (2–4 runs, Tiny Aya, 250–2k episodes, 1–3 epochs) | Kaggle 2x T4 | 6–12 h | $0 (Kaggle quota) |
| Optional Aya Expanse 8B SFT comparison (1 run) | Kaggle T4 or HF L4 | 4–7 h T4 / ~2–3 h L4 | $0 or ~$2–3 |

| Eval runs | Laptop / Kaggle | several h | $0 |
| **Total paid** | | | **≈$5–15 of $20–30**, with Modal's free $30/month as an extra buffer if available |

- Kaggle need: ~15–25 T4-session-hours over the 10 days, within the ~30 h/week quota but competing with the user's other jobs.
- Decision gates: (a) if SFT dev success stays below ~10–15%, skip GRPO (groups will be all-zero) and do a second RFT round instead. (b) If vLLM does not load Cohere2 on L4 within ~1 h, run without vLLM on L40S or drop to RLOO/DPO mode 3.
